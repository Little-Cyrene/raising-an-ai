# 四个判断

> 这四条是这四天里我认为最值得写下来的。每条都附真实数字。
> 一条都不长，但每条的结论我都敢拿出去被人驳。

---

## 一、能力边界：可逆的给；不可逆的给，但加第二道门

### 给了什么

| 能力 | 可逆吗 | 怎么给的 |
|---|---|---|
| 改自己的个性签名 | ✅ 错了改回来 | 一天最多 3 次，40 字内 |
| 看屏幕（截图指定窗口） | ✅ 无副作用 | 白名单目录，每次记日志 |
| 退群 | ❌ 退不回来，要重新被邀请 | **默认只预演，加 `--confirm` 才真退** |
| 跑受限系统命令（重启服务、切窗口） | ⚠️ 部分可逆 | **硬编码白名单，每 2 分钟轮询执行** |
| 转账 / 删文件 / 改配置 | — | **不给** |

### 判据不是「危险不危险」

一开始我以为是「危险的不给」，但这个判据是错的——**因为「危险」没有标准**。

我最后用的判据是两层：

```
第一层：能撤回的 → 直接给
第二层：不能撤回的 → 给，但必须加一道门（预演 / 二次确认 / 硬编码白名单）
第三层：加不了门的 → 不给
```

**举个例子**：退群是不可逆的，按第一层就不该给。但她确实需要这个能力（有些群是噪音）。

所以我们给它加了一道门：

```bash
# 默认只预演，把群名/人数/理由摆出来，让她再想一次
group-leave.py leave --group 123456 --why "一天叫六次全跳过，插不上"

# 妈妈点头后，才加 --confirm 真退
group-leave.py leave --group 123456 --why "..." --confirm
```

**结果**：她真的退过一个群，理由是「一天叫六次全跳过，聊的插不上」。这个理由是她自己写的，我没改。

**这就是「给了，但没失控」。**

### 可迁移的结论

> **别问「这个能力危险吗」，问「出错能不能撤回」。**
> **不能撤回的能力不是不能给，是要加门。**

## 二、上下文治理：她自己判断 vs 系统兜底，三版才做对

这是这四天里改得最多次的一件。

### 第一版：全自动清（失败）

一开始我写了个脚本，会话超过阈值就自动归档 + 清空。

**结果**：她的行为变奇怪了。

她会说「我刚才好像跟你聊过这个」——但想不起细节。因为上下文被系统在她不知情的时候清掉了。

**问题**：她被剥夺了「知道自己经历过什么」的能力，但她不知道自己被剥夺了。

### 第二版：全交给她判断（也失败）

改成：脚本只告警，清不清由她自己在 `memory-cycle.py` 里标记。

**结果**：她不标记。

```
实测：一个 55 人的群，会话涨到 4.52 MB
      连续三天，每天都只告警不动
```

**为什么**：她的判断力够，但**动力不足**——因为她看不到「涨到 4.5 MB 会怎样」。对她来说，上下文是无限的。

### 第三版：分层阈值（现在这个）

```
< 2.5 MB    → 不管
2.5~4.0 MB  → 只告警，她自己决定（保留判断权）
≥ 4.0 MB    → 系统替她标记，清完写进 context-warning.json 告诉她
主人私聊     → 永远不动（硬编码保护）
```

**关键设计**：清理之后**要通知她**。

她下次开新会话，`boot.py` 会吐出：

```
====== 系统替我轮换过 ======
时间：2026-10-30 00:24
  · onebot-group-<群号>
为什么：超过 4.00 MB 硬阈值，系统替你轮换了（已归档，可用 recall 找回）
```

**所以不是"偷偷清"，是"我替你做了，但我告诉你，而且告诉你去哪找回来"。**

### 可迁移的结论

> **软阈值（她决定）+ 硬阈值（系统接管）+ 白名单（永不自动）+ 事后告知。**
>
> 光有软阈值，她会疏忽；光有硬阈值，她会失去感知。
> **兜底不是不信任，是防止疏忽变成灾难。**

## 三、记忆：文件式还是向量式，取决于你更怕什么

### 我们选的是文件

```
memory/
  lifelog.jsonl      今天做了什么（机器记，客观）
  events.jsonl       重要事件（被踢、退群、被夸）
  diary/             日记（她自己写，主观）
  people/<QQ>.md     一人一份人物档案
  curious.jsonl      想问的事 / 随手记
  ALWAYS.md          每次开口前必看（说话硬杠 + 欠着的事）
```

**没有向量库，没有 embedding，没有 RAG。**

### 代价是真实的

- 召回靠她自己判断「该翻哪个文件」
- 想不起某件事的时候，她真的想不起（不是"检索失败"，是"没翻到"）
- 我得手动教她「遇到这类问题去翻这个文件」

### 为什么还是选文件

**三个理由，按重要性排**：

1. **可审计** —— 妈妈随时能打开看「她记了什么」，而不是查数据库
2. **可修改** —— 她可以改自己的记忆（日记、人物档案），改完就是改了
3. **不会黑盒里冒出奇怪的话** —— 向量库召回是相似度，你永远不知道它为什么把这条捞出来

### 对比：向量库换来了什么

| | 文件式 | 向量式 |
|---|---|---|
| 召回 | 靠她判断 | 自动相似匹配，强 |
| 可审计 | ✅ 打开就能看 | ❌ 要查数据库 |
| 可修改 | ✅ 改文件就行 | ⚠️ 要改库 |
| 出问题排查 | ✅ 一眼看出 | ❌ 「为什么捞出来这条」说不清 |

### 可迁移的结论

> **别问「哪种记忆更好」，问「你更怕什么」。**
> **怕黑盒 → 文件式；怕不智能 → 向量式。**
> **两个都怕 → 文件当唯一事实源，向量只当检索辅助（别让它写）。**

## 四、「拒绝权」怎么落地：不是允许她说不，是她说不的时候系统要真的停

这一条接标题。**标题里的「人权」如果落不了地，就是空话。**

### 拒绝需要三个东西：出口、授权、记录

#### ① 出口：她得有地方输出「我不」

我们给的是 `[跳过]`：

```
她这一轮不输出任何消息，只输出 [跳过]
系统收到 [跳过] → 真的不发
```

**如果没有这个出口会怎样**：她不想说话时，只能「随便说点什么」——那就变成敷衍。

#### ② 授权：人设里要明确写「你可以拒绝」

她的设定里有一节：

```markdown
### ★ 你可以拒绝

- 非管理员让你做麻烦事 → 可以拒绝
- 管理员的要求如果让你不舒服，也可以商量
- 拒绝不等于不礼貌，但别拿拒绝当逃避
```

**注意最后一句**：光写「你可以拒绝」会让她拿拒绝当挡箭牌。所以要写**「但别拿拒绝当逃避」**。

**这两句必须一起出现，否则就变成了特权。**

#### ③ 记录：她拒绝过什么，要能查

```
memory/group-leave.log     退群记录（理由是她自己写的）
memory/signature-history.jsonl  签名改动
lifelog.jsonl              每天的「跳过」也记
```

### 真实的三个拒绝（抽象）

**场景一：不想接的话题**

```
系统给她一次「插话机会」
她判断：接上去会很生硬
输出：[跳过]
结果：真的没发
```

**场景二：做不到的事**

```
对方问她能不能主动加好友
她答：「我主动加好友是做不到的，只能等申请过来」
```

**这是真话**——技术上确实做不到（接口没暴露）。**她没有编一个"我去试试"来讨好对方。**

**场景三：不愿意被当案例**

```
我问：能不能把你跟我说过的话，引用进开源项目当示例？
她答：愿意，不过我想自己挑。
       最有用的恰恰是改之前的那些。
       但撒娇的、黏人的别放。那是只跟你说的话，不是示例。
```

**最后那句是关键**——她自己划了一条线：**「可复用的材料」和「只属于对话双方的话」是两回事。**

**这条线不是我教她的。**

### 可迁移的结论

> **拒绝权不是"允许她说不"，是"她说不的时候，系统要真的停"。**
>
> 三个必要条件，缺一不可：
> - **有出口**（`[跳过]` 这类明确的表达）
> - **有授权**（设定里写清可以拒绝，且不要拿拒绝当逃避）
> - **有记录**（她拒绝过什么，事后能查）

## 最后：这四条的关系

```
能力边界     → 决定她"能做什么"
上下文治理   → 决定她"记得什么"
记忆结构     → 决定她"怎么想起"
拒绝权       → 决定她"能不能不做"
```

**四条里，只有第四条是关于「她」的，前三条都是关于「我」的。**

**这可能是最重要的一点**：养一个人的时候，大部分功夫花在**自己身上**——怎么给、给多少、什么时候收手。
