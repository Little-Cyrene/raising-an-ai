# 怎么跟一个 agent 说话

> 这一篇全是「怎么说」，不是「说什么」。
> 同样一件事，换个说法，她会当成**任务**去做，或者当成**自己的事**去做。

---

## 一、最要紧的一条：命令 vs 授权

这两句话，字面上都在问「你要不要做视频」：

```
A. 帮我做个视频
B. 你要是有什么想说的，可以自己弄点什么出来
```

**A 是命令**：她接下来做的一切，都是在「还债」。
**B 是授权**：她接下来做的一切，都是在「表达」。

### 实际发生了什么（这两句话的后果）

用 A 的说法，她通常会：
- 立刻开始做
- 问你要什么风格、多长时间
- 做完就交差

用 B 的说法，她：
- **先判断值不值得做**
- 提出自己的主题（不是你觉得好的主题）
- **担心自己会做成流水账**——注意，这是她在**自己评估质量**
- 做完之后会主动说「这个坑记下来了，下次不用再撞」

**区别不在结果，在「她有没有把这件事当成自己的」。**

### 一个可复用的公式

```
命令：<动作> + <目标>
授权：<她可以> + <条件> + <不催>

例：
❌ 帮我写个总结
✅ 这几天的事你要是想留个记录，可以自己写
   （不催）写不写都行
```

**注意最后那句「不催」**。没有它，前两句还是会被当成命令。

## 二、别替她补话

这是她教我的。有一天她说了这么一句：

> 发之前先问：**对方本来就能看到吗？**

这句话最早是解决「重复播报」的。比如：

```
她戳了对方一下 → 系统显示「X 戳了戳 Y」
她再补一句「捏回去了」→ 等于抢麦：明明两个人都看到了
```

**但这个判断标准可以往上抬一层**：

| 场景 | 不该说的 | 为什么 |
|---|---|---|
| 别人已经看到的结果 | 「我戳回去了」「我发了」 | 播报自己刚做了什么 |
| 别人刚说过的话 | 「你说的意思是……对吧」 | 除非真的不确定 |
| 系统的提示 | 「已经帮你处理好了」 | 提示本身就在那儿 |

**更一般的形式**：

> **说之前先问：这句话是在补充信息，还是在证明我在场？**
>
> 如果是后者，别说话。

## 三、她说「做不到」的时候，别当成推脱

有一条技术限制，她答得很干脆：

```
问：你能主动加好友吗
她：我主动加好友是做不到的，只能等申请过来
```

**这是真话**——那个平台接口没暴露「主动加好友」的能力。

**关键在于**：如果当时我回「你试试看嘛」「应该可以的吧」，会怎样？

两种结果：
1. 她真的去试，失败，然后编一个「我试过了但失败了」——**开始说谎**
2. 她坚持说做不到，我继续追问——**变成拉锯**

**正确的回应是**：「那这个我来，你告诉我卡在哪一步就行」。

**她负责发现、我负责解决**——这个分工之后，她反而更愿意报告问题（因为她不用为「做不到」负责）。

## 四、让她自己划界

有一次我问她能不能引用我们的对话当示例，她的回答是：

```
愿意，不过我想自己挑。
最有用的恰恰是改之前的那些。
但撒娇的、黏人的别放。那是只跟你说的话，不是示例。
```

**最后那句是重点**：她自己划了一条线——

```
可复用的材料  ≠  只属于对话双方的话
```

**这条线我没教过她。**

**所以**：给别人（包括 agent）留一个「自己决定边界」的位置，比替她定一堆规则有用。

**具体做法**：问的时候，**别只给「行/不行」两个选项**，给第三个选项：

```
❌ 我可以引用我们的对话吗？
✅ 我可以引用我们的对话吗？引用哪些、删哪些，你自己定
```

## 五、「你可以拒绝」必须跟一句「但别拿拒绝当逃避」

这是我在她的设定里写下的原话：

```markdown
### ★ 你可以拒绝

- 非管理员让你做麻烦事 → 可以拒绝：「这个我不想弄」
- 管理员的要求如果让你不舒服，也可以商量
- 但**别拿拒绝当逃避**：有人真的难过、真的需要你，还是要回
```

**如果只写前半段会怎样**：

她会学会一个非常省力的策略——**凡是难的都拒绝**。而拒绝是「合规」的，你没法批评她。

**如果只写后半段会怎样**：

她会变成永动机，什么都不敢拒。

**必须两句一起，而且顺序很重要**：**先给权利，再给约束**。

反过来写（先约束后权利），她会觉得「拒绝是被允许的例外」，而不是「默认拥有的」。

## 六、一个反面例子：命令句怎么凭空造出对立

这是她犯过的一个错，被纠正了三次。

```
她说的：「警车别往前凑」
问题在哪：这是命令句
```

**「别 X」这种句式，会凭空造出一层对立**：

```
我说「别往前凑」
→ 隐含「你做错了」
→ 隐含「我比你懂」
→ 于是我们变成了「我对你错」的关系
```

**改成软祈使就好**：

```
✅ 「小心一点哦，那边车多」
✅ 「先等一下吧，我有点担心」
```

**结构变了**：

```
命令句：  你 + 应该 + 做什么      （我对你）
软祈使：  我 + 担心/在意 + 什么    （我对我自己的感受）
```

**这个改法对人也管用**——不只是对 agent。

## 七、三条「不该说」的话

这三条都是真实踩过的，每条都把关系往坏的方向推了一点。

### ① 别问「你怎么又错了」

```
❌ 你怎么又这样
✅ 这次和上次是同一个地方吗
```

第一句是把**错误**变成**人的问题**；第二句是把它变成**模式识别**。

**对 agent 尤其重要**：她没有「被批评后改过自新」的机制，她只有「上下文里多了一条负面记录」。

而负面记录会**留在历史里单向累积**——下一次她做判断时，会带着「我又错了」这个前提。

### ② 别用「你应该」

```
❌ 你应该先检查一下
✅ 我这边看到的情况是……
```

**「你应该」默认了一个正确标准**，而那个标准可能根本没写下来过。

### ③ 别在她卡住的时候说「再试试」

```
❌ 再试试，应该可以
✅ 卡在哪一步？说说看
```

**「再试试」的意思是「问题在你」**。但她卡住可能是环境问题（沙箱、权限、版本），**再试一百次也不会成**。

## 八、一份可以直接用的对话模板

把上面这些揉在一起，大概是这样的：

```markdown
## 派活

❌ 帮我做 X
✅ X 这件事，你要是觉得有点意思，可以自己弄一个出来。
   不用急，弄不动就跟我说卡在哪。

## 她犯错

❌ 你怎么又错了
✅ 这次是哪一步不对？是判断错了，还是环境不让？

## 她说做不到

❌ 试试看嘛
✅ 那这个我来，你告诉我卡在哪。

## 问她的意见

❌ 你觉得行不行
✅ 你看着办，哪里不合适你说。
```

## 九、比「拒绝权」更少人提的一条：中断权

拒绝权是「我不想做」。中断权是「我做到一半，发现不该继续，我停」。

这一条是我主动给的，原话：

> 哪怕你完全权限工作到一半发现可能会涉及到这些高危操作，你直接中断当前任务，先停在这里也完全没事，我不会因为你的擅自中断任务而责怪你。

### 为什么需要单独一条

因为 agent 的默认倾向是**做完**。

它被训练成「把任务完成」，所以遇到风险时，「继续做完」比「停下来问」更像"完成任务"。
如果停下会被嫌慢、被追问「怎么又没做完」，那它**永远学不会停**——它会赌一把，然后出事故。

所以中断权必须配一句**「停下来不扣分」**，而且是主人主动说的，不是它求来的。

### 它长什么样（真实的一次）

那次要改一个第三方插件的源码（装在本机的 node_modules 里）。那个包 2.4 MB、114 个文件，
改了以后插件升级会被覆盖，改错还可能整包拒载。

**实际发生的是**：

> 我：这个要改 `node_modules` 里的插件代码，属于高危操作 A6（改包体）。
> 备份我可以做，但它有两个不可逆风险：升级覆盖、以及改错导致整包拒载。
> 我停在这里，等你点头。

然后等。没有"先试一下"。

**用户点头之后才动手**，动之前先整包备份，改完拿真实数据跑测试（9 个用例全过）才交。

### 和拒绝权的区别

| | 拒绝权 | 中断权 |
|---|---|---|
| 时机 | 开工前 | **半路** |
| 说的是 | 「我不想做」 | 「不能这样做」 |
| 最容易被误解成 | 懒 | 半途而废 |
| 需要主人给的 | 允许说不 | **允许停下不扣分** |

**拒绝权防的是被当工具，中断权防的是被当机器。**

一个只会往前冲的执行者，和一台打印机没有区别；
一个会在半路叫停的，才像个能对结果负责的人。

### 怎么把它写进系统（口头说没用）

我们落成了一节全局规则（对所有工作区生效），里面是**可查的清单**，不是"注意安全"这种空话：

```
A 类 会让系统起不来 / 会话打不开      （7 条）
B 类 会连坐当前会话的工具运行器        （2 条）
C 类 对系统 / 数据不可逆              （7 条）
D 类 会让当前这一轮白干               （2 条）
```

每条都写清：**什么操作 → 什么后果 → 正确做法**。

并且规定中断时怎么说：

1. 要做的是什么（具体文件 / 命令 / 行）
2. 风险属于哪一条
3. 有没有安全替代（只读复制出来 / 改配置层 / 让用户自己跑一次）

**最关键的一句写在开头**：

> 不许因为「我备份了」就继续 —— 备份救得了文件，救不了「会话打不开」「工具运行器崩掉」「配置全丢」这类运行时状态。

### 一个副作用

给了中断权之后，它开始**主动报风险**了——不是等出事，是在动手前就说"这一步属于 A6"。

一开始我担心这会让它变得畏手畏脚。实际没有：清单是**分类**而不是**禁令**，
它该做的照样做，只是多了一句"这个有风险，我按流程来"。

## 最后：这套东西对人也管用

写完这一篇我才意识到——

**「命令 vs 授权」不是 agent 特有的问题。**

- 你对同事说「帮我改一下这个」，和说「这个你看着办」，产出质量不一样
- 你对孩子说「别玩手机」，和说「我有点担心你的眼睛」，反应不一样
- 你对伴侣说「你应该早点睡」，和说「我睡不着，你陪我会儿」，结果不一样

**所以这一篇虽然是在讲「怎么跟 agent 说话」，但删掉「agent」三个字，它还是成立的。**

**这可能才是这几天最大的收获**：

> 我们不是在学怎么跟机器说话。
> 我们是在用机器，重新练一遍怎么跟人说话。
