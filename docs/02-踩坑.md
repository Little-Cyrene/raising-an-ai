# 踩坑清单

> 20 条，全部实测。每条都有「现象 / 原因 / 绕法」。
> **按「浪费了多少时间」排序**，不是按类别。

---

## 先给结论

这四天里，**真正花时间的不是「功能做不出来」，是「做出来了但环境不让它跑」**。

20 条里，**11 条是环境问题**（沙箱、权限、编码、路径），只有 4 条是模型行为，5 条是我自己的操作失误。

**所以给后来者一句实话**：

> 搭一个能自己办事的 agent，写代码大概占 30% 的时间。
> 另外 70% 花在「让它在一个真实操作系统上稳定跑起来」。

## A. 沙箱与权限（最费时间的一类）

### 1. 沙箱不让子进程开管道

**现象**：

```python
subprocess.run([sys.executable, "say.py", text], capture_output=True)
# 沙箱下静默失败，音频没生成，也不报错
```

`capture_output=True` 会创建管道（pipe），沙箱拦截这个操作。

**原因**：Windows 沙箱限制子进程的句柄继承 / 管道创建。

**绕法**：让子进程**直接写文件**，不要读它的输出。

```python
subprocess.run([sys.executable, "say.py", text, "--out", out_path],
               timeout=180,
               stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
# 然后检查 out_path 是否存在
```

**关键点**：`stdout/stderr` 要显式给 `DEVNULL`，不能留默认（默认也是管道）。

**耗时**：第一版工具在这上面卡了半天，最后是「她」自己试出来的（她跑的时候撞到，改了代码）。

---

### 2. Low Integrity Level 下，窗口操作全废

**现象**：

```powershell
# 全部返回 Access is denied
PostMessage WM_CLOSE        # 想关窗口
SetForegroundWindow         # 想切前台
SendInput                   # 想模拟按键
schtasks /query             # 想查别的计划任务
```

**原因**：进程跑在 **Low Mandatory Level**（S-1-16-4096）。Windows 的 UIPI（User Interface Privilege Isolation）会拦截低完整性进程对高完整性窗口的任何操作。

**但注意**：**读屏幕像素是能用的**（`ImageGrab`），只有「操作窗口」被拦。

**绕法**：把需要提权的操作**挪到一个高完整性的进程**里做，用文件当邮箱：

```
她写请求文件 → 计划任务（高完整性，每 2 分钟轮询）→ 执行 → 写结果文件 → 她读结果
```

这个模式叫「受限提权通道」，见 `code/admin-channel/`。

**耗时**：一整天。因为一开始以为「权限不够就申请管理员」，但实际上**连 `schtasks /run` 都被拦**——不能按需触发提权任务，只能等它自己轮询。

---

### 3. `-WindowStyle Hidden` 挡不住计划任务的控制台窗口

**现象**：计划任务每隔 1 分钟闪一下黑框，用户能看见。

```powershell
# 这样没用
schtasks /create /tn X /tr "powershell.exe -WindowStyle Hidden -File a.ps1" ...
```

**原因**：`-WindowStyle Hidden` 是 PowerShell 自己的参数，它隐藏的是**PowerShell 的**窗口，但**任务计划程序在启动进程时已经创建了一个控制台**。

**绕法**：用 VBS 包一层。

```vbscript
' admin-op-hidden.vbs
CreateObject("WScript.Shell").Run "powershell.exe -NoProfile -File ""C:\path\a.ps1""", 0, False
```

`0` = 隐藏窗口，`False` = 不等待。

任务里写：`wscript.exe //B //NoLogo C:\path\admin-op-hidden.vbs`

**耗时**：半小时（试了 `-WindowStyle Hidden`、`conhost`、`Start-Process -WindowStyle Hidden`，全不行）。

---

### 4. 改配置不重启 = 没改

**现象**：改了 `reasoningEffort: low → medium`，测试发现**行为没变**。

**原因**：配置在进程启动时读一次。改文件对运行中的进程无效。

**绕法**：改完立刻重启，或者**先验证「这次改动生效了吗」**再继续。

```powershell
# 判断依据：进程启动时间 vs 配置文件修改时间
(Get-Process -Name node).StartTime
(Get-Item "$config").LastWriteTime
# 如果 StartTime 早于 LastWriteTime → 没生效
```

**代价**：这条今天犯过三次（QQ 空间概率、端口配置、推理档位）。

**教训**：**「改完必须验证」不是洁癖，是必要步骤**。

## B. Windows 脚本交付（写脚本的人最容易栽的地方）

### 5. `.cmd` 用 UTF-8 存中文，会被 GBK 读碎

**现象**：双击一个 `.cmd`，满屏「不是内部或外部命令」。

**原因**：`cmd.exe` 按系统当前代码页（简体中文是 **GBK/CP936**）读文件，而编辑器存的是 UTF-8。中文字节被拆成乱码，**整行命令被拆烂**。

**绕法（按可靠性排序）**：

1. **最稳**：`.cmd` 里**不写任何中文**，纯 ASCII
2. 次稳：存成 GBK（但编辑器不好控制）
3. 不推荐：`chcp 65001` 开头（只影响后续输出，不影响文件解析）

**验证**：

```powershell
# 数一下非 ASCII 字节，必须是 0
$b = [IO.File]::ReadAllBytes("x.cmd")
($b | Where-Object { $_ -gt 127 }).Count
```

---

### 6. 右键运行 `.ps1` 时的「安全警告」不是提权

**现象**：双击 `.ps1`，弹「是否运行」，点「是」，然后脚本里所有 `schtasks` 操作报「拒绝访问」。

**原因**：「安全警告」只是在**解除 MotW**（Mark of the Web，下载文件带的标记），它跟权限**完全无关**。脚本还是以当前用户权限跑的。

**绕法**：要提权就得走 UAC：

```powershell
# 脚本内部检查是不是管理员
if (-not ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()
    ).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)) {
    Write-Host "请用管理员权限运行"
    exit 1
}

# 或者用 .cmd 包一层，主动申请提权
powershell -Command "Start-Process powershell -Verb RunAs -ArgumentList '-File','a.ps1'"
```

---

### 7. `Tee-Object -Append -Wait` —— 这个参数不存在

**现象**：日志函数每次调用都报「找不到参数 Wait」。

**原因**：`-Wait` 是 `Get-Content` 的参数（等待文件变化），`Tee-Object` 没有。

**绕法**：要「追加写 + 立刻刷盘」，用 `Add-Content`：

```powershell
function Write-Log($msg) {
    "[{0}] {1}" -f (Get-Date -Format 'yyyy-MM-dd HH:mm:ss'), $msg |
        Add-Content -Path $log -Encoding UTF8
}
```

**教训**：**这条被我写进教训清单了——「语法检查通过 ≠ 能跑」**。

`Tee-Object -Append -Wait` 在编辑器里不报错（因为 `-Wait` 只是参数名，PS 会在运行时才查）。**必须真跑一次。**

---

### 8. `Set-Content -Encoding UTF8` 会加 BOM，把 JSON 弄坏

**现象**：

```
Unexpected token '﻿' in JSON at position 0
```

**原因**：Windows PowerShell 5.1 的 `-Encoding UTF8` 会写 **BOM**（`EF BB BF`）。JSON 解析器不认识这个字符。

**绕法**：写文件用 .NET 方法，显式指定无 BOM：

```powershell
[IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding $false))
```

**读的时候**用 `utf-8-sig` 兼容带 BOM 的旧文件。

---

### 9. 控制台 CP936，中文全乱码

**现象**：脚本打印的中文在日志里是 `锟斤拷`，正则匹配全错。

**绕法**：每次开脚本先设两行：

```powershell
$env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [Text.Encoding]::UTF8
```

Python 脚本里**也要**显式 `io.open(..., encoding="utf-8")`，别依赖默认。

## C. 模型行为（agent 特有的坑）

### 10. 模型会把「挑措辞的过程」当正文发出去

**现象**：她跟人私聊时，连发 9 条这种：

```
他说「...」——正好是他现在的昵称，有点自嘲的意思
回应：接这个梗，但别太损

定：「好家伙，改名就是为了说这句」——「好家伙」不太像她人设
回复思路：
一句话：
或者更软俏皮一点：
```

**真正的回复只有最后一句**，前面全是内心戏。

**触发条件**：**「要回得巧妙」的场景**（接梗、起外号、调侃）。不需要思考的对话完全正常。

**原因**：模型把 reasoning 内容写进了 `content`，不是写进独立的 reasoning 通道。

**绕法（三层）**：

1. **出站正则过滤**（兜底）

```javascript
const META = /(回复思路|思路[:：]|回应[:：]|^\s*定[:：]|^\s*一句话[:：]|^或者更|他说「|我要接住|不太像她人设)/;
if (META.test(line)) continue;   // 整行丢弃
```

2. **提示里明确禁**（治本，但不保证）

```markdown
⛔ 别把「想梗的草稿」发出去：不要出现「回复思路：」「定：」「一句话：」这类话。
  那些是你自己在挑用词，对方只想要最后那句。
```

3. **验证**：拿真实的泄漏样本跑一遍正则，**看 6 条该丢的丢了、4 条该留的留住了**

**教训**：**只靠提示不够，只靠过滤也不够。两层都要。**

---

### 11. `[引用]` 这种「假格式」会被当成真指令

**现象**：她发出去的消息里有一行 `[引用]。: @某人 你是我的宝宝`。

**原因**：她的提示里写了「想引用就带 `[引用]`」，但**平台根本没有这个语法**。引用是 API 的一个字段（`{"type":"reply","data":{"id":"123"}}`），不是文字标记。

模型看到「要引用」，就照着提示里的格式写了出来。

**教训**：

> **提示里写的「格式」，模型会当成真的语法去执行。**
> 所以写提示时，**明确区分「这是文字」和「这是 API 参数」**：
> - 要 API 调用 → 写成 `action: xxx, params: {...}`
> - 要文字 → 别用方括号包命令词

---

### 12. `reasoning` 不只在 `thinking` 事件里

**现象**：用 `--json` 看事件流，以为只过滤 `thinking` 就够了。实际检查发现：

```json
{"type":"thinking","text":"User asks: ... They want a..."}      ← 有推理（预期）
{"type":"text","text":"` if the format includes closing tags..."}  ← 也混了
{"type":"final","text":"` if the format includes closing tags..."} ← 同样混
```

**原因**：模型在需要思考的问题上，会把推理**写进正文**，不只是 reasoning 通道。

**怎么验证**：

```
问一个需要思考的问题（不是"1+1"），用 --json 看 text/final 里有没有英文分析
```

**绕法**：

- 如果要「精确问答」，必须**过滤输出**，或者要求固定前缀（`答案：...`）再解析
- 如果要「自然对话」，那过滤规则要覆盖**所有正文通道**

## D. 我自己的操作失误（最该记的一类）

### 13. 用 python `open("w")` 改文件，把文件写成 0 字节

**现象**：

```python
s = io.open(p, encoding="utf-8").read()
s = s.replace(old, new)
io.open(p, "w", encoding="utf-8").write(s)   # ← 如果这里抛错
```

`open(p, "w")` **打开就截断了文件**。如果后面的 `write` 因为任何原因失败（编码、参数、异常），文件就变成 **0 字节**。

**我的实际损失**：一个 14 KB 的工具（做过一条真视频的）变成空文件，`.pyc` 只有 210 字节（编译失败残留），**恢复不了**。

**绕法（三条，都做到）**：

1. **改文件用编辑器工具**，别用脚本读写
2. 真要脚本改：**先写临时文件 → 校验 → 再 `os.replace`**
3. **改之前先备份**：`cp file file.bak-<时间戳>`

**教训**：这条最该记，因为它**不报错、不报警、直接毁掉东西**。

---

### 14. 杀父进程会连坐子进程

**现象**：想重启一个服务，杀了它的 pid，结果**端口彻底没了**（连子进程一起死了）。

**原因**：那个 pid 是 venv 的 launcher，真正的服务是它 **spawn 的子进程**。杀父 → 子被连带清理。

**绕法**：

```powershell
# 先看父子关系，再决定杀哪个
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like "*目标脚本*" } |
    Select-Object ProcessId, ParentProcessId, Name
```

**如果是 venv 的父子对**：杀**子**（真服务），父会自动退出；或者两个都杀但**等端口释放**再重启。

---

### 15. 复制目录到同名目录，会嵌套

**现象**：想备份 `sessions/onebot-x/` 到 `backup/`，结果变成 `backup/onebot-x/onebot-x/`。

**原因**：`Copy-Item -Recurse` 到**已存在的同名目录**时，会把源**放进**目标里面。

**绕法**：

```powershell
# 先确认目标不存在，或者显式指定完整目标路径
if (Test-Path $dst) { Remove-Item $dst -Recurse -Force }
Copy-Item $src $dst -Recurse
```

**教训**：**复制/移动前先验证目标路径**，别假设它不存在。

---

### 16. `Stop-Process` 会让工具运行器崩溃

**现象**：在一个工具调用里执行 `Stop-Process`，整个工具返回：

```
Windows Job runner exited with exit code 4294967295
```

（4294967295 = `0xFFFFFFFF` = -1，进程被强制终止）

**原因**：被杀的进程可能在同一个作业对象里，连坐。

**绕法**：用 `taskkill /F /PID`，或者干脆走计划任务：

```powershell
& cmd /c "taskkill /F /PID $pid"
```

## E. 平台与依赖

### 17. 插件 peerDependencies 版本代差，装不上别硬装

**现象**：

```
dsh: installation rejected: Plugin xxx@0.2.0 is incompatible with dsh 0.2.0-rc.2:
     peerDependencies {"@deepseek-ai/dsh-compaction":"^0.1.1-rc.2"}
```

去 npm 查：

```
dsh-compaction 只有 0.0.1-rc.5（不满足 ^0.1.1-rc.2）
```

**结论**：**这个插件是为更新版宿主写的**。强装（`--accept-risk`）可能让整个会话崩掉。

**纪律**：**同一条路两次没成，不许试第三次**。换方案（自己实现那个功能，30 行代码的事）。

### 18. 平台没暴露的接口，就是没有

**现象**：想做「自动同意好友申请」。查了 8 个可能的接口名，全部 404：

```
get_friend_request_list  → 404
get_friend_requests      → 404
get_friend_apply_list    → 404
...
get_group_system_msg     → ✅ 能用，但里面只有「群邀请」和「加群请求」
```

**原因**：平台只把好友申请当**普通私聊消息**上报（`[收-私] xxx：请求添加你为好友`），**没有带 `flag`**。而同意好友的 API 需要 `flag`。

**绕法**：**做不到就承认做不到**。

最后的方案是：她发现有人加好友 → 私聊提醒主人 → 主人手动点。

**这个「降级方案」反而更好**：一天没几条好友申请，手动点更快也更安全。

**教训**：

> **不是所有「看起来该有的能力」都该有。**
> 有些平台限制，是在保护用户。

### 19. 离线模式加载 LoRA，必须给 `weight_name`

**现象**：

```
ValueError: When using the offline mode, you must specify a `weight_name`.
```

**原因**：设了 `HF_HUB_OFFLINE=1` 之后，库没法通过 hub API 猜文件名。

**绕法**：

```python
pipe.load_lora_weights(os.path.dirname(lora_path),
                       weight_name=os.path.basename(lora_path))
```

**顺带**：`from_single_file` 加载单文件模型时，它还会去下载 config。离线时要把本地 config 目录传进去：

```python
StableDiffusionXLPipeline.from_single_file(
    model_path, config=local_config_dir, local_files_only=True, ...)
```

### 20. ffmpeg `drawtext` 的转义是地狱

**现象**：字幕里出现 `:` 或 `,` 就报错，或者整句消失。

**原因**：`drawtext` 的 `text=` 参数在 filtergraph 里，这些字符有特殊含义：

| 字符 | 必须写成 |
|---|---|
| `:` | `\:` |
| `,` | `\,` |
| `'` | 换成 `’`（单引号会破坏引号配对） |
| `%` | `\%` |
| `\` | `\\` |

**绕法**：

```python
esc = (text.replace("\\", "\\\\").replace(":", "\\:")
           .replace("'", "’").replace("%", "\\%").replace(",", "\\,"))
```

**更稳的**：把文本写进一个文件，用 `textfile=` 而不是 `text=`。

```python
f"drawtext=fontfile='{font}':textfile='{txt_path}':fontsize=42:..."
```

如果只能记三条：

| 排名 | 坑 | 为什么最贵 |
|---|---|---|
| 1 | **沙箱不让开管道**（#1） | 静默失败，不报错，最难查 |

**共同点**：**都是「不报错」的失败。**

**所以给后来者一句**：

> 做 agent 最费时间的不是「报错」，是「没报错但也没生效」。
> 每改一处，都要有一个**能验证「这次真的变了吗」**的办法。

## F. 刚踩的（还没归类）

### 21. 让 agent 审自己的文档会"超时"——但真正的原因我一开始搞错了

> **更正（2026-10-30 凌晨）**：
> 我最初把原因归成「1.46 MB 会话太大 + 任务太重」，还据此加了阈值和告警。
> **后来发现真因是：一个授权弹窗把整个轮次阻塞了。**
> 保留这一条，是因为**这个误判本身很有教育意义**——见文末「为什么这个误判值得留着」。

原文如下（我当时的判断，部分是错的）：

**现象**：

```
让她读桌面上的 3 个 markdown（26 KB）并给出审阅意见
→ 600 秒后超时：「等待模型回复超时（已静默等待约 600 秒），任务仍在后台运行」
```

**先排除的**：

```powershell
# 1. 文件权限对不对？（白名单）
her-pc.py read "C:\Users\...\审阅摘要-只看这篇.md"
# → 能读，权限没问题

# 2. 她有没有真读？（看调用日志）
Get-Content memory\her-pc.log
# → 文件不存在，说明连调用都没走到
```

**真正的两个原因**：

1. **任务本身重**：3 个文件 × 读入 + 审阅 = 好几轮工具调用
2. **会话太大**：她那个私聊会话 **1.46 MB**，每轮请求都要带着它

**叠加效果**：1.46 MB 上下文 + 3 次文件读 + 审阅思考 → 单轮响应超过 10 分钟。

**绕法**：

1. **别让她读全文，给她摘要**
   ```
   26 KB 原文 → 压成 2 KB「只需要回答这一个问题」的摘要
   ```
2. **一次只让她做一件事**：「有没有哪句会露出来」，而不是「审阅并给出意见」
3. **看会话大小**：超过 1 MB 就该提醒她（或者主人自己）开新会话

**可迁移的结论**：

> **给 agent 的任务，要按「它的上下文有多大」来设计，不是按「这活对人有多简单」。**
> 对人来说「读三个文件给点意见」是五分钟的事；
> 对 1.46 MB 上下文的 agent 来说，这是**要跑十分钟的重活**。

**顺带**：这也解释了为什么「让她一次做完整条视频」很难——
视频要 6~8 轮工具调用，每轮都带着全部上下文。**轮次才是成本的单位，不是字数。**

#### 为什么这个误判值得留着

我当时的证据链是这样的：

```
① 会话 1.46 MB（确实很大）
② 派了读 3 个文件的任务（确实重）
③ 600 秒超时（确实发生了）
→ 结论：会话太大 + 任务太重
```

**每一条都是真的，但结论错了。**

真因是：**她读的是工作区外的文件（桌面）→ 触发审批 → 整个轮次阻塞 → 等用户点"允许"。**

**三条真证据拼成一条错结论，这就是"相关性不等于因果"的现场。**

**而且我据此做了三件事**（加 1 MB 告警线、写进 ALWAYS、写进这篇文档），**全建立在错结论上**。

**唯一让它暴露的，是用户听到了「授权提示音」**——一个跟我所有分析都无关的线索。

**教训**：

> 当你发现「A 很大、B 很重、然后出事了」，**先问一句「还有没有别的解释」**。
> 尤其是：**你的观测手段（日志）里看不到的那个维度**。
>
> 我当时能看到的只有「没有 turn/end」「CPU 不动」——**看不到"有个弹窗在等"**。
> 而那个弹窗不会出现在任何日志里。
